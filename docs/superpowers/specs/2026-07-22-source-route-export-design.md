# 采集路线独立导出设计

## 目标

在线索库顶部提供明确的“采集路线”导出筛选，使用户可以单独导出阿里国际站、1688、启信宝等采集路线产生的线索，同时保留现有行业、分配状态、城市、关键词和线索等级规则。

## 交互设计

在线索库顶部导出工具栏中，在“行业”和“分配”筛选附近增加“采集路线”下拉框。选项为：

- 全部路线
- 启信宝
- 天眼查
- AI 1688搜企
- 抖音线索
- 1688采集
- 阿里国际站
- 中国制造网+天眼查
- 1688普通页面

导出按钮规则：

- “导出筛选”导出 A、B、C、D 全部等级，使用所选采集路线，并叠加当前关键词、城市、行业和分配状态等条件。
- “导出高价值”只导出 A、B 等级，使用所选采集路线，并叠加相同筛选条件。
- “当前模块”继续使用线索列表当前模块页签，不受顶部采集路线下拉框影响。
- 导出完成后继续沿用现有规则，将实际导出的线索标记为“已分配”。

## 数据与接口

不新增数据库字段。`lead_record.source_type` 继续作为底层采集路线标识。

前端导出请求使用已有的 `source_group` 字段表达用户选择。采集路线与来源类型的映射由后端现有 `SOURCE_GROUP_TYPE_MAP` 统一维护，其中“1688普通页面”可同时覆盖页面助手和页面导入两种底层来源。

后端为导出请求增加采集路线白名单校验。空值和 `all` 表示全部路线；未知值直接返回参数错误，不能退化为导出全部线索。

## 文件命名

导出文件名包含采集路线名称：

- 选择阿里国际站：`阿里国际站_线索导出_YYYYMMDD_HHMMSS.xlsx`
- 选择全部路线：`全部路线_线索导出_YYYYMMDD_HHMMSS.xlsx`

发生同秒重名时继续使用现有数字后缀机制。

## 错误处理

- 未知采集路线：接口返回 422 参数错误，不生成文件，也不修改分配状态。
- 筛选结果为空：仍生成只包含表头的 Excel，并返回 `total_count=0`，保持现有导出行为。
- 文件写入失败：不更新线索分配状态。

## 测试与验收

后端测试覆盖：

- 阿里国际站路线只查询 `alibaba_international`。
- 1688普通页面路线同时查询页面助手和页面导入。
- 未知路线被拒绝。
- 导出文件名包含路线名称。
- 采集路线与行业、城市、分配状态等条件可以叠加。

前端验证覆盖：

- 采集路线选择正确进入“导出筛选”和“导出高价值”请求。
- “当前模块”仍使用当前线索模块，不被独立导出路线覆盖。
- TypeScript 构建通过，工具栏在现有桌面宽度下不发生文字重叠。
